# 节点删除与登录 IP 信任

删除节点会自动撤销该节点提供的登录 IP 信任，现有实现已具备这一行为。

节点列表里的“信任 IP”开关属于节点记录 `Client.trust_login_ip`。它不会把 IP
复制到账号的手动白名单；登录时会读取仍存在且启用了信任的节点，再核对在线状态、
当前探针令牌、服务端观察到的公网来源 IP，以及列表可见的节点 IPv4/IPv6。

## 可见 IP 与连接来源

节点上报地址和实际连接来源分别展示。管理员接口返回 `connection_source_ip` 与
`ip_trust_eligible`，只在管理员响应中添加，不写入数据库，不向访客暴露。
来源与节点上报地址不同可能由 NAT64、NAT 或代理导致，界面显示“中转出口”和真实来源 IP；
仅凭地址差异不能确诊 NAT64，因此提示使用“可能经过 NAT64 或代理”。

自动登录豁免必须同时满足：节点勾选信任、总阀门开启、节点在线且令牌和连接仍有效，
以及登录来源既等于连接来源、又属于列表可见的节点 IPv4/IPv6。比较采用规范化 IP，
兼容 IPv6 压缩表示及 IPv4 映射地址。

未显示的中转出口不能隐式获信任。不一致或缺少有效连接时，新增信任返回 HTTP 409；
旧的已开启选择保留，但豁免暂停，关闭仍可操作。节点地址改变后，登录校验即时按新地址判断，
不依赖前端提示。只上报地址而没有真实连接验证也不能取得豁免。

手动白名单保持独立的显式授权，不会因使用 NAT64 自动添加中转 IP。

## 点击节点行的删除按钮后

单台删除和批量删除使用 `POST /api/admin/client/:uuid/remove`，桥接到
`admin:removeClient`。该方法删除节点数据库记录，并清掉该节点的连接和来源 IP
缓存、最新上报缓存；后续登录不能再通过该节点获得免 2FA 待遇，无需再去删除一条自动白名单。

免 2FA 的资格按仍有效的信任来源判定：

| 情况 | 删除节点后该 IP 的登录行为 |
| --- | --- |
| 只有被删除节点信任该 IP | 账号已开启 2FA 时，重新登录需要验证码 |
| 另一台仍被信任且在线的节点，其可见 IP 也与同一出口一致 | 另一台节点仍可提供免 2FA 待遇 |
| 账号手动白名单也添加了同一 IP | 手动条目继续生效，需要在设置里单独撤销 |

因此“该节点的信任自动消失”成立，但共用 IP 的其他独立授权仍按各自设置生效。
白名单始终只免除登录验证码，仍需正确的账号密码；节点删除也不会注销先前已登录的会话，
需要注销会话时使用会话管理。
